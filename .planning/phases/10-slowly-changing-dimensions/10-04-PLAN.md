<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| staging.customers (durable bronze) -> SCDPublisher's per-key recompute read | Already-validated pipeline data, no untrusted external input reaches this read directly |
| SCDPublisher's write path -> normalized.customers | The DELETE+INSERT this plan performs is the primary write mechanism the new DELETE grant (plan 10-01, T-10-02) exists for |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-10-01 | Tampering | scd.py's DELETE-detection, touched-key discovery and per-key recompute SQL | mitigate | Every interpolated fragment is a literal, hand-written identifier; staged_run_ids/customer_id/snapshot_max_event_ts cross exclusively via bound parameters, matching merge.py/referential.py's T-04-01/T-08-11 precedent, reaffirmed here for the new module |
| T-10-03 | Tampering / DoS | Race between concurrent writers producing a corrupted/partial version chain | mitigate (structurally here, live-tested in plan 10-08) | SCDPublisher.publish() never takes its own advisory lock and never commits -- the caller (publish_ingest, unchanged since Phase 4) holds pg_advisory_xact_lock('publish:normalized.customers') for the whole call, serializing every writer; the exclusion constraint (plan 10-01) is the backstop if that discipline is ever violated |
| T-10-09 | Repudiation | A recomputed version's lineage columns silently losing traceability to the bronze row that produced it | mitigate | Every INSERTed VersionRow carries _run_id/_file_id/_batch_id/_source_row_number/_record_hash/_record_hash_version from the specific bronze row that started that version, never a blank/aggregate value -- preserves this platform's Core Value (traceability) through a DELETE+INSERT replace, not just an append |
</threat_model>
