<objective>
Deliver the PR-gating fast smoke subset (D-19/D-20): an ephemeral kind cluster, in GitHub Actions,
running the PR's own just-published `pr-<number>` images (not main's last build), proving the four
things a PR must prove before merge is worth attempting — the stack boots including Kyverno, one
real DAG succeeds, Vault's identity model holds, Kyverno's admission policy holds.

Purpose: CICD-09's "a pull request spins up an ephemeral kind cluster... and runs E2E" requirement,
scoped to the fast subset D-20 defines — the full suite is plan 11-05's job, gated to merge only.
This is also where the real cross-cutting risk 11-RESEARCH.md flags (Pitfall 5) gets resolved:
without deliberately pointing the cluster at the PR's OWN images, this workflow would silently test
main's last build and never catch a regression the PR itself introduces.

</objective>

**As a** platform operator who did not build this system, **I want to** trust that the whole
environment provably rebuilds from the repository, every catalogued failure mode has a passing
test, and CI gates every change end-to-end, **so that** I can operate, recover and extend the
platform without relying on tribal knowledge.

A PR that merges without ever running its own code through a real cluster is a promise, not a
proof — this plan is what makes it a proof.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PR-authored code -> an ephemeral cluster with real (if scoped-down) infrastructure | The whole point of D-20 is to run untrusted-until-reviewed PR code somewhere real; the ephemeral, single-use nature of the kind cluster is the containment boundary |
| `DOCKERHUB_USERNAME`/`DOCKERHUB_TOKEN` repo secrets | Only ever used for a read-only Docker Hub login to raise pull-rate limits, never write access |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-38 | Elevation of Privilege | A malicious PR's own code running inside the ephemeral cluster | accept | this is the intended, contained blast radius of D-20 by design — the cluster is single-use, torn down at job end, and holds no production secrets (Vault's own dev-mode bootstrap, MinIO's dev credentials — all already documented as isolated/reproducible per SEC-13) |
| T-11-39 | Information Disclosure | `DOCKERHUB_TOKEN` leaking via job logs | mitigate | `docker/login-action` never echoes the password; the token is a repo secret, never inlined in workflow YAML |
| T-11-40 | Tampering | The smoke subset silently testing main's image instead of the PR's | mitigate | Task 1's entire purpose — `AIRFLOW_IMAGE_OVERRIDE_*` + `ci-set-workload-images.sh` explicitly and verifiably point every workload at the PR's own `pr-<number>` GHCR tag before any check runs |
| T-11-SC | Tampering | `helm/kind-action` (or `tools/k8s/install_*.sh`) | mitigate | already-pinned per CLAUDE.md (`v1.14.0`) or already-established checksum-verified local installers; no new unvetted tool introduced |
</threat_model>
