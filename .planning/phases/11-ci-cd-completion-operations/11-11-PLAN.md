`_table_checksum` will report a false mismatch on every rebuild (it hashes lineage columns a
rebuild deliberately re-mints), and `record_reconciliation`'s own per-file grain does not, by
itself, answer "does table T today equal table T before the drop." This plan builds exactly the
small amount of genuinely new code those two pitfalls require — nothing more.

reconciliation module.

## Phase Goal

**As a** platform operator who did not build this system, **I want to** trust that the whole
environment provably rebuilds from the repository, every catalogued failure mode has a passing
test, and CI gates every change end-to-end, **so that** I can operate, recover and extend the
platform without relying on tribal knowledge.

INCR-07 is this phase's capstone precisely because it exercises raw immutability, config
versioning, historical schema resolution, idempotency and reconciliation together — but none of
that means anything if the pre/post comparison itself can produce a false mismatch or a false
match. This plan is where that arithmetic gets proven correct in isolation.
</context>
