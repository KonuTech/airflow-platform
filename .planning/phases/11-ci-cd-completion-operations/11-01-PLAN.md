<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner -> GHCR | The runner pushes an image using the ephemeral `GITHUB_TOKEN`; a compromised action could exfiltrate or poison this push |
| GitHub Actions runner -> Sigstore (Fulcio/Rekor) | The runner requests a short-lived signing certificate via OIDC; the identity asserted (repo + workflow path + ref) is what a verifier later trusts |
| Repository source -> build context | `docker build` reads the full checked-out tree; a malicious dependency or Dockerfile change is the same trust boundary every build in this repo already crosses |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Tampering | Every `uses:` action reference | mitigate | pinned by full 40-char commit SHA, never a floating tag — a compromised upstream release cannot silently repoint an already-referenced version; enforced by Task 2's policy test |
| T-11-02 | Tampering | Published image content | mitigate | cosign keyless signing binds a Sigstore-issued, GitHub-OIDC-backed certificate to the exact image digest; plan 11-03's Kyverno policy later enforces verification at admission cluster-wide |
| T-11-03 | Elevation of Privilege | `GITHUB_TOKEN` scope | mitigate | `packages: write`/`id-token: write` scoped to the job only, workflow-level floor stays `contents: read`; token is auto-revoked at job end |
| T-11-04 | Repudiation | trivy scan results | accept | findings live only in this run's job log for this plan; no persistent vulnerability ledger is built here (out of scope) — acceptable since GHCR's own security surface retains scan-adjacent metadata independently |
| T-11-05 | Tampering | Base image supply chain (`python:3.12-slim-bookworm`) | mitigate | trivy scans the fully-built image (base + app layers), catching a compromised or stale base layer before publish, gated `exit-code: 1` |
| T-11-SC | Tampering | GitHub Actions used by this plan | mitigate | every action (`docker/build-push-action`, `docker/login-action`, `docker/setup-buildx-action`, `sigstore/cosign-installer`, `aquasecurity/trivy-action`) is pre-vetted `Approved` in 11-RESEARCH.md's Package Legitimacy Audit (verified org, non-archived, recent release) — no `[ASSUMED]`/`[SUS]` entries, no blocking human-verify checkpoint required |
</threat_model>
