# BLOCKING CONSTRAINTS — Read Before Anything Else

- [ ] CONSTRAINT: Never run `make rebuild-from-raw` or any other destructive live-cluster command without explicit user confirmation — it drops schemas and wipes MinIO buckets. Ask first even if a prior session already got approval; approval does not carry forward automatically.
- [ ] CONSTRAINT: After ANY host interruption (restart, Docker crash, usage-limit pause), before touching the cluster: check `docker exec <kind-node> mount | grep /mnt/dags` for all 3 nodes (a restart can silently swap the real bind mount for an empty tmpfs, freezing Airflow scheduling with zero errors) and check `kubectl get pods -n vault` (Vault re-seals on node restart — run `make vault-unseal` if not 1/1 Ready). Both happened repeatedly this session.
- [ ] CONSTRAINT: When dispatching a live-CI-debugging Agent(isolation="worktree") and later wanting to "resume" it, do NOT dispatch a second Agent() with isolation="worktree" — that creates a completely separate fresh worktree with none of the original's commits. Use SendMessage to the original agent's id/name to resume it in place. This mistake happened once this session (caught before damage, but wasted a dispatch).
- [ ] CONSTRAINT: A background Monitor task can survive what looks like a full context reset. Before re-arming a monitor after a "[Monitor timed out]" notification, check `ListAgents` isn't the right tool for Monitor tasks — if in doubt whether a prior monitor is still alive, prefer checking the actual run status via `gh api` directly over blindly re-arming, and if you do re-arm, note the old task_id so you can `TaskStop` it once you're sure it's a genuine duplicate. Three duplicate monitors ended up running simultaneously this session before being caught.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Trusting `gh api` unauthenticated | Public GitHub API is rate-limited to 60/hr; burns through fast when polling workflow runs. Always `export PATH="$HOME/.local/bin:$PATH"` and use authenticated `gh api`, never raw unauthenticated `curl`. | advisory | Use `gh api` for all GitHub API calls, not `curl https://api.github.com/...` |
| Alembic invoked without correct `-c` path | `alembic` (bare) or `alembic -c alembic.ini` fails with "No 'script_location' key found" — the real config lives at `migrations/alembic.ini`, not repo root. | advisory | Always `uv run alembic -c migrations/alembic.ini <command>`, or use `make migrate-analytics` which already gets this right. |
