**As a** platform operator who did not build this system, **I want to** trust that the whole
environment provably rebuilds from the repository, every catalogued failure mode has a passing
test, and CI gates every change end-to-end, **so that** I can operate, recover and extend the
platform without relying on tribal knowledge.

procedure must be one command, not a memory of which Helm flags to pass.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI job summary/artifact | Coverage HTML could theoretically leak source-line detail to anyone with read access to a public repo's Actions runs — already true of the repo itself, no new exposure |
| `rollback` target -> live cluster | An operator with `kubectl` access to the cluster can redeploy arbitrary prior SHAs; this is the SAME privilege `make image-csv-processor`/`cluster-up` already assume |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-14 | Information Disclosure | `htmlcov/` artifact | accept | this is a public repository; source and coverage detail are already visible in the repo itself, the artifact adds no new disclosure |
| T-11-15 | Tampering | `rollback SHA=<attacker-supplied>` | accept | `SHA` is an operator-supplied local input, not attacker-controlled network input; the target only ever references `ghcr.io/<owner>/...`, the fixed, already-namespaced registry path — it cannot be redirected to an arbitrary registry |
| T-11-SC | Tampering | `actions/upload-artifact` | mitigate | pinned by full commit SHA per this repo's existing convention; 11-RESEARCH.md's Package Legitimacy Audit lists it Approved (first-party `actions` org, current release) |
</threat_model>
