<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Fork PR -> `GITHUB_TOKEN` | A PR from outside this repository must never receive write access to GHCR via this workflow |
| PR-tagged image -> ephemeral-kind cluster (plan 11-04) | An unsigned or unscanned PR image reaching a live cluster would defeat the entire supply-chain story this phase builds |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-06 | Elevation of Privilege | Fork-originated `pull_request` run | mitigate | GitHub itself forces a read-only `GITHUB_TOKEN` on fork-originated `pull_request` runs (platform-level, not application-level) — this plan's own explicit `if:` guard additionally short-circuits the push/sign/scan steps and logs why, rather than letting the push step fail confusingly |
| T-11-07 | Tampering | `pr-<number>` tagged image left unsigned | mitigate | Task 1 wires cosign sign + trivy scan unconditionally for both trigger types — proven by Task 3's non-vacuity test asserting no `event_name == 'push'` guard exists on those steps |
| T-11-08 | Information Disclosure | GHCR package left listing a superseded/vulnerable `pr-<number>` build indefinitely | mitigate | D-11's automatic cleanup on PR close (`ghcr-cleanup.yml`) bounds the exposure window |
| T-11-09 | Repudiation | `docker buildx imagetools create` retagging without rebuilding | accept | the retagged manifest is byte-identical to the already-scanned, already-signed SHA image; no new content is introduced, so no new scan is needed — this is a documented property, not a shortcut around scanning |
| T-11-SC | Tampering | `actions/delete-package-versions` (last tagged 2024-01-16) | accept | 11-RESEARCH.md's own Package Legitimacy Audit flags this as "Approved with caveat" — first-party `actions` org, non-archived, narrow scope; Task 2 explicitly verifies its current input shape against the live `action.yml` rather than trusting a remembered API surface |
</threat_model>
