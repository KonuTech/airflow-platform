## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Kubernetes API server <-> Kyverno admission webhook | Every Pod CREATE/UPDATE across every namespace is intercepted here; a webhook outage or misconfiguration (`failurePolicy`) determines whether the cluster fails open or closed |
| Cluster-wide policy <-> pinned third-party images | The D-16 exception list is the ONLY sanctioned bypass of signature verification — its accuracy is itself a security control |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-10 | Tampering | Any pod image not on the exception list | mitigate | `ImageValidatingPolicy` with `validationActions: [Enforce]` denies admission unless a valid cosign signature from this repo's own `publish.yml` identity is found |
| T-11-11 | Denial of Service | `webhookConfiguration.failurePolicy: Fail` | accept | a Kyverno outage blocks ALL new pod creation cluster-wide (fail-closed by design, per this project's Core Value of never silently admitting an unverified artifact); accepted because the alternative (`Ignore`) would silently defeat D-14's entire purpose the first time the controller has a bad day |
| T-11-12 | Tampering | Stale/incomplete D-16 exception list | mitigate | Task 2 enumerates every pinned third-party reference by reading every `helm/values/*.yaml` file directly, not from memory; a future new chart addition that forgets to update this list fails LOUD (the new component's pods are denied, visibly, on the very next cluster-up) rather than silently |
| T-11-13 | Spoofing | An attacker-controlled workflow signing under a similar-looking identity | mitigate | `subjectRegExp` is anchored (`^...$`) and scoped to this exact repository + workflow file path, not a broad wildcard |
| T-11-SC | Tampering | Kyverno Helm chart | mitigate | 11-RESEARCH.md's Package Legitimacy Audit: `kyverno/kyverno`, CNCF project, non-archived, pinned to a 6-week-field-tested release (3.8.2) rather than the 2-day-old latest — `[ASSUMED]`/`[SUS]` do not apply, no blocking checkpoint required |
</threat_model>
