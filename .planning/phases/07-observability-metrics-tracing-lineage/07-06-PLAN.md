<objective>
Extend `scripts/vault-bootstrap.py` with the one genuinely new Vault-consumer shape this phase
introduces: Grafana has no Vault client at all (unlike Airflow's native `VaultBackend` or
`hvac`-in-pod for ETL — the two tiers Phase 5 deliberately established as the only ones), so its
credentials must land in a Kubernetes Secret, materialized from Vault-stored values by the same
trusted, already-authenticated bootstrap script that already performs this exact
generate-password/`kubectl exec`/write-to-Vault-KV sequence for `etl_app`.

Purpose: after this plan, `make vault-bootstrap` (idempotently) rotates in a fresh `grafana_reader`
PostgreSQL password and provisions the operator's chosen alert-webhook URL, and materializes both
as a single Kubernetes Secret Grafana's `envFromSecret` values key (Plan 07-07) can reference by
name — the raw credential value never appears in git or in any committed Helm values file, only the
Secret's name does, matching this project's `airflow-metadata`/`fernetKeySecretName` precedent
exactly.
Output: `_ensure_grafana_secrets()`; the `grafana-alert-webhook` Kubernetes Secret in the
`monitoring` namespace.
</objective>
