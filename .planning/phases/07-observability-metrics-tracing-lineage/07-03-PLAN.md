<objective>
Stand up the Observability tier's ingress: a new `monitoring` namespace, the standalone
`open-telemetry/opentelemetry-collector` chart (the single OTLP endpoint both Airflow's traces and
`dataplat`'s metrics/traces will converge on) and the single-binary Tempo chart (the tracing
backend this project genuinely lacks today — `.claude/CLAUDE.md` §H is explicit that
kube-prometheus-stack ships none). Both charts get committed `local`/`ci` values pairs and join the
existing offline `helm template` + `kubeconform -strict` CI gate (D-16) — CI never deploys them
live, only validates their shape.

Purpose: after this plan, there is a real, reachable OTLP ingress point in the cluster and a real
place traces can land — every later plan in this phase (dataplat's real OTLP export, the Airflow
trace injection, Grafana's Tempo datasource) points at infrastructure that already exists and is
already proven to render correctly, rather than a forward reference.
Output: `monitoring` namespace; OTel Collector + Tempo running (once `make cluster-up` re-runs);
`make manifests` covers eight charts instead of five.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Any in-cluster pod → OTel Collector (4317/4318) | Unauthenticated OTLP ingress — any workload in the cluster can push telemetry |
| OTel Collector → Tempo | Internal, in-cluster-only trace export |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-08 | Denial of Service | Unauthenticated OTLP receiver (4317/4318) | accept | ClusterIP-only, no ingress, no host-reachable endpoint — only pods already inside this kind cluster's own pod network can reach it, matching this project's existing acceptance of Vault's own unauthenticated-transport local-dev posture (Vault's own `tls_disable = 1` argument) |
| T-07-09 | Tampering (supply chain) | `opentelemetry-collector`, `tempo`, and their container images | accept | Both are well-known CNCF/Grafana-Labs-maintained OSS projects with established public image provenance; the package-legitimacy gate applies to npm/pip/cargo installs specifically, not Helm chart pulls from their own project-maintained repositories |
| T-07-10 | Information Disclosure | Trace/metric payloads crossing pod boundaries | accept | Telemetry carries operational metadata (dataset/stage/status labels, span names/timings) only — no row content, no PII, no credentials ever enter a span attribute or metric label per this phase's own bounded-label design (Plan 07-02) |
</threat_model>
