<objective>
Wire the two `dataplat.observability` no-op seams (`metrics.py`, `tracing.py`) to a real
OpenTelemetry SDK backend — `configure()` builds one real `MeterProvider`/`TracerProvider` with an
OTLP/HTTP exporter when given an endpoint, and stays a genuine no-op otherwise — and add the D-04
bounded label set (`dataset`+`stage`+`status`) to the two call sites already threaded through
`pipeline/engine.py` since Phase 3. This is the library half of OBS-08 (bounded-cardinality
metrics) and the foundation OBS-10 (tracing) builds on in later plans.

Purpose: after this plan, any `dataplat` process configured with an OTLP endpoint emits real,
bounded-cardinality metrics and real spans — provable locally with a throwaway HTTP receiver, no
cluster needed — while every existing caller (`pipeline/engine.py`'s two `metrics.increment(...)`
calls, `tracing.start_span("pipeline.run_streaming.chunk")`) keeps working unmodified in shape.
Output: real `metrics.py`/`tracing.py`, D-04-compliant labels on both `RaggedRowGuard.apply()`
counters, a passing integration test proving genuine OTLP delivery.
</objective>
