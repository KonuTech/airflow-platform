<objective>
Build SCHEMA-01's conservative type inference: given a column's sampled raw string values, infer one
of `ColumnContract`'s closed type set (`string`/`integer`/`decimal`/`date`/`timestamp`/`boolean`),
biased hard toward `string` whenever inference could be wrong in a way that loses information — a
value like `001234` stays a string even though every character is a digit, because coercing it to an
integer would silently strip the leading zeros that make it a valid identifier.

Purpose: one of the five independently-parallel detector plans. This capability is explicitly
bootstrap-only (CONTEXT.md canonical_refs: "computed in-pod as a bootstrap aid; never applied
automatically to the load path — locked: contract wins"). It exists to help a human author a
`columns:` contract, and to give the future schema-evolution classifier a fallback signal for a column
the contract does not yet declare — it is never itself the authority for what gets loaded.
Output: `infer_column_type`, corpus-fixture-parametrized, returning a suggestion type plus the
evidence that produced it (never silently authoritative).
</objective>
