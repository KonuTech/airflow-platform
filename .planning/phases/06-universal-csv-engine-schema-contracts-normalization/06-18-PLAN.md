(built and unit-tested in isolation by 06-08) are wired into the REAL call chain: `discover_files`'s

and `CsvSource.open()` actually reads every grouped part as one logical stream. This closes

`part-00001` would each discover and process as two independent files, and `part-00001`'s first data row
would very likely be misread as a header.

is ever silently coerced") both depend on this wiring existing somewhere. 06-08 built the primitives and
explicitly deferred wiring; 06-14 wired the five detectors + compression into `CsvSource` but never
referenced multipart; 06-16 wired the normalizers + `discovery.py`'s idempotency-key/business-date
extensions but never referenced it either. This plan is that missing integration step, sequenced last
(wave 5) because it depends on `source.py`'s final shape (06-15) and `discovery.py`'s final shape (06-16) —
both already landed by the time this plan runs, and both are files this plan also modifies.
Output: `AssignmentDocument.additional_parts`, `discover_files`'s real multipart grouping, `CsvSource`'s
multi-part `open()`, `cli.py`'s assignment-to-CsvSource wiring, and a real Postgres+MinIO-backed test
