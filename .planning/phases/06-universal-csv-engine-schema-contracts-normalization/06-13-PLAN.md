<objective>
Build SCHEMA-04/SCHEMA-05's schema-evolution classifier as a pure, DB-independent function comparing
two column lists (the dataset's currently-recorded/contract schema vs. this file's observed schema)
and producing exactly one of two outcomes per the phase's locked decisions: a genuinely new column is
COMPATIBLE — return a `SchemaChangeFinding` value, never raise, per D-01's "detect + record only,
never auto-DDL"; a column disappearing, a retype, or (by construction, since a rename IS a
disappearance) a rename are all BREAKING — raise `IncompatibleSchemaError` before any row is staged,
per D-02's "the whole file fails, nothing loads."

Purpose: one of Wave 2's independently-parallel plans — this classification function has no analog
anywhere in the current codebase (06-PATTERNS.md's own "No Analog Found" table names it explicitly:
"genuinely new domain logic... no prior phase implements any classification logic to model against").
It is pure and DB-independent by design: comparing two in-memory column lists needs no
`meta.schema_versions` row, no header detector, and no config-contract wiring beyond the `ColumnContract`
shape 06-02 already defined — those integrations belong to a later wiring plan (06-15).
Output: `classify_schema_change`, unit-tested against every combination the dlt 3×4 matrix and D-01/
D-02/D-04 name, plus QUAL-12's compatible-and-breaking coverage.
</objective>
