<interfaces>
`tools/corpus/generators.py`'s determinism primitives (verified this session, full read) are the
building blocks to reuse, NOT the `Manifest`/`Fixture`/`generate_corpus` declarative machinery
itself (that machinery is for the fixed, committed byte-level-edge-case corpus and has no "N
files, one per day" concept): `stream_for(master_seed: str, name: str) -> random.Random` (R1 — every
fixture/day draws from its own stream, derived from `sha256(f"{master_seed}|{name}")`); rows are
built via `rng.random()` arithmetic only (R2), never `choice`/`randint`; text is encoded and written
in binary mode (R3); no wall-clock/OS-entropy call anywhere (R6 — `tests/policy/
test_generator_determinism_rules.py` enforces this by source inspection and will need to pass
against this new module too).

`configs/datasets/customers.yaml`/`orders.yaml` `columns:` blocks (read this session) are the exact
schema this generator's rows must match: customers = `customer_id, name, country, birth_date
(%Y-%m-%d), event_ts (%Y-%m-%dT%H:%M:%S%z)`; orders = `order_id, customer_id, order_date
(%Y-%m-%d), amount (decimal)`.

`scripts/ingest-demo.py`'s `_read_minio_credentials`/boto3-client-building pattern (lines ~260-320)
and `tests/e2e/slice/test_backfill_reentry.py`'s `app.put_object(Bucket="raw", Key=..., Body=...)`
call (line ~642) are the exact upload mechanism plan 09-11 will use with THIS plan's generated
bytes — this plan does not perform any upload itself (kept pure/testable, no network I/O, no S3
client dependency).
