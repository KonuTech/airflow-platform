<objective>
Extend the existing, presence-only `_BATCH_COMPLETE` marker gate (LOAD-11, opt-in, unexercised
until now) to actually READ and PARSE its object body, and thread the parsed control total
(`expected_row_count`/`expected_checksum`) all the way from `discover_files` through the frozen
`AssignmentDocument` into the `stage` pod's `RunContext` — the plumbing plan 09-07 needs before it
can compare the manifest's claim against what actually got staged (VALID-06).

Purpose: D-23 gives the manifest real purpose for the first time; RESEARCH.md Pitfall 5 is explicit
that today's gate never calls `get_object` at all — this is genuine new code, not a "wire up an
existing field" one-liner.
Output: A new `BatchCompleteManifest` Pydantic model, an extended marker gate that reads the body,
`AssignmentDocument`/`RunContext` carrying the parsed totals end to end.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `raw` bucket object body (`_BATCH_COMPLETE` marker) → `BatchCompleteManifest` | Attacker-influence-adjacent: the marker arrives via the same untrusted `raw` bucket as CSV content, not a trusted internal source |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-06 | Tampering | `_BATCH_COMPLETE` marker body claiming a false `expected_row_count`/`expected_checksum` | mitigate | This plan only PARSES and THREADS the value — the comparison-and-discrepancy-flagging logic (plan 09-07) always treats `expected_*` as a claim to verify against the actually-loaded count, never as ground truth to suppress an alert; a malformed body withholds the batch entirely rather than being partially trusted |
| T-09-07 | Denial of Service | An oversized or deeply-nested manifest body | mitigate | `expected_checksum` is `max_length=128`; `extra="forbid"` rejects any additional top-level key; `model_validate_json` on a small, flat, two-field schema has no unbounded-recursion surface |
| T-09-08 | Information Disclosure | Manifest parse-failure log line | accept | Logs `marker_key`/dataset name only, never the raw body content, matching this codebase's existing structured-logging discipline |
</threat_model>
