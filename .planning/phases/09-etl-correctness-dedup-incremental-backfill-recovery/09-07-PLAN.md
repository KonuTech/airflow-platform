<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `_BATCH_COMPLETE` manifest's `expected_row_count` → `meta.reconciliation_results.expected_row_count` | Attacker-influence-adjacent value (plan 09-03), now persisted and COMPARED against, never trusted as authoritative over the actual staged count |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-13 | Tampering | A malicious `expected_row_count` crafted to make `control_total_discrepancy` read as zero, masking a real data-loss event | mitigate | The comparison direction is fixed: `control_total_discrepancy = expected_row_count - output_count`, computed server-side in SQL against the ACTUALLY staged count — a manifest cannot make a genuine loss disappear, it can only make its OWN claim look consistent or inconsistent with reality, and the raw `output_count`/`rejected_count` columns remain independently queryable regardless |
</threat_model>
