<objective>
Create `meta.v_run_recovery`, the single SQL view answering LOAD-06's "what succeeded, what
remains, retry-or-rollback" question across the WHOLE pipeline (D-16), templated directly on
`meta.v_customers_lineage`'s "drop + recreate whole view" pattern (migrations 0012/0026/0030).

Purpose: D-15 established recovery is retry-only (rollback structurally cannot apply — every stage
commits atomically or not at all); this view makes that fact directly queryable, never implying a
rollback path exists.
Output: `meta.v_run_recovery` (view), a small `get_run_recovery_status` read helper on the metadata
repository for tests/observability to use without hand-writing the join.

    `down_revision = "0032"`. Module docstring cites D-14/D-15/D-16 and copies migration 0030's
    "Postgres has no ALTER VIEW... " rationale verbatim. `upgrade()` executes a single `CREATE VIEW
    meta.v_run_recovery AS` statement: `SELECT r.run_id, r.dataset_id, r.status AS run_status,
    r.logical_date, r.dag_id, r.dag_run_id, sl.status AS stage_load_status, sl.lease_expires_at AS
    stage_load_lease, db.status AS dbt_build_status, pb.status AS publish_status, CASE WHEN
    r.status = 'SUCCEEDED' AND pb.status = 'SUCCEEDED' THEN 'complete' WHEN sl.status IN
    ('FAILED', 'PENDING') OR sl.status IS NULL THEN 'retry stage STAGE_LOAD' WHEN db.status IN
    ('FAILED', 'PENDING') OR db.status IS NULL THEN 'retry stage DBT_BUILD' WHEN pb.status IN
    ('FAILED', 'PENDING') OR pb.status IS NULL THEN 'retry stage PUBLISH' ELSE 'in progress' END AS
    next_action FROM meta.ingestion_runs r LEFT JOIN meta.run_stages sl ON sl.run_id = r.run_id AND
    sl.stage_name = 'STAGE_LOAD' LEFT JOIN meta.run_stages db ON db.run_id = r.run_id AND
    db.stage_name = 'DBT_BUILD' LEFT JOIN meta.run_stages pb ON pb.run_id = r.run_id AND
    pb.stage_name = 'PUBLISH'` — the `next_action` column literally spells "retry stage X", never
    implying rollback (D-15). Then `GRANT SELECT ON meta.v_run_recovery TO etl_app` and `TO
    grafana_reader` (zero grant to `dbt_app`, matching D-14's Airflow-side-write-only design).
    `downgrade()` drops the view.
