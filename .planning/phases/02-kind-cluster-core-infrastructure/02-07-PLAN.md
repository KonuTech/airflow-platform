<objective>
Make CI fail on an invalid manifest or chart, offline of any cluster: render both values profiles
for all five pinned charts, validate every rendered document with `kubeconform -strict` against
Kubernetes 1.35.5, and prove the gate is live by watching it reject a deliberately-broken manifest.

Purpose: ROADMAP success criterion 5 has two halves. The rendering half is proved here; the sizing
half is plan 02-08. This half is worthless unless the validator can actually discriminate — and
`kubeconform` silently cannot validate a CloudNativePG `Cluster` CR without a CRD schema, so a
naive setup passes everything and certifies nothing.

Output: a pinned kubeconform, vendored CNPG CRD schemas regenerable from the pinned chart, the
render-and-validate pipeline behind `make manifests`, its CI invocation, and the non-vacuity test.
</objective>

<user_story>
**As a** platform engineer opening a pull request that edits a Helm values file,
**I want to** be told by CI that my manifest is invalid before it reaches a cluster,
**so that** a typo in a values key is a red build in seconds rather than a half-applied release I
discover twenty minutes into a bootstrap.
</user_story>
