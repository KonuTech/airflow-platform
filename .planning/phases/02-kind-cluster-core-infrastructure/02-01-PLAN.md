<objective>
Prove the whole Phase 2 architecture on one thin path: a developer with nothing installed but
Docker runs `make cluster-up` and gets a 3-node kind cluster, a local OCI registry, the five
namespaces, and a real ingress controller answering on host port 80 through a
`*.localtest.me` hostname — then `make cluster-down` removes it.

Purpose: every later component in this phase (both PostgreSQL clusters, MinIO, Airflow) is an
additional stage on this exact path. If the creation-time surface, the registry, the stage
ordering, the Helm 4 wait strategy or the host↔cluster port publish is wrong, it is wrong here,
after one commit, rather than after five.

Output: the committed creation-time surface (`kind/cluster.yaml`), the bootstrap spine
(`scripts/cluster-up.sh` + `scripts/stages/` + `scripts/helm-install.sh` +
`scripts/wait-for.sh`), the first component (ingress-nginx) in both values profiles, and the
pinned host toolchain.
</objective>

recreating the cluster.

    `kubernetes/namespaces.yaml` — one multi-document manifest declaring the five D-13 namespaces:

    `scripts/helm-install.sh` — a sourceable helper exposing `helm_install <release> <chart-ref>
    <namespace> <version-var-name> <values-basename>`. It sources `helm/versions.env`, resolves
    the values file as `helm/values/${PROFILE:-local}/<values-basename>.yaml`, refuses if that file

    strategy is written deliberately: in Helm 4.2.3 `--atomic` no longer exists, `--wait` is a
    strategy whose default when the flag is omitted is `hookOnly`, and RESEARCH measured a CNPG

    `--create-namespace` — namespaces are owned by `kubernetes/namespaces.yaml` alone, so no two
    releases manage the same object.

    each a `kubectl wait --for=condition=...` with an explicit timeout. Prefer
    `--for=condition=Available` on a Deployment over `rollout status`, which returned
    "successfully rolled out" in 0.107 s when the Deployment's generation had not yet been
    observed. No `sleep` as a readiness mechanism anywhere.

    `scripts/cluster-up.sh` — the only bootstrap entry point. Sources `helm/versions.env`; ensures
    the pinned kind and helm binaries via `tools/k8s/install_kind.sh` and
    `tools/k8s/install_helm.sh`; creates the cluster with
    `kind create cluster --name "$CLUSTER_NAME" --config kind/cluster.yaml` only when
    `kind get clusters` does not already list it, so a re-run against a live cluster is a no-op
    rather than an error and an interrupted bootstrap is resumed by re-running; then executes every
    `scripts/stages/*.sh` in ascending `LC_ALL=C` lexical order, exporting `PROFILE`,
    `CLUSTER_NAME` and `KUBECTL_CONTEXT=kind-$CLUSTER_NAME`. Set `set -euo pipefail` and echo each
    stage name before running it. Every stage must be re-runnable.

    `scripts/cluster-down.sh` — deletes the cluster if `kind get clusters` lists it, otherwise
    prints that there was nothing to delete and exits 0. Leaves the registry container running:

## Planner note — D-09 implemented by substitution, recorded rather than silent

D-09 is locked as "one target per component, ordered by Make prerequisites". This plan implements
component ordering as `scripts/cluster-up.sh` iterating `scripts/stages/*.sh` in `LC_ALL=C` order,
with a `stage-%` pattern rule giving each component one invocable unit. Every other element of D-09
is honored exactly: Make remains the only gate definition, CI calls `make` and nothing else, each
stage is one `helm upgrade --install` against a committed values file, and the hand-written
readiness waits D-09 anticipates live in `scripts/wait-for.sh`.

What the substitution buys is that adding a component is adding one file rather than editing the
spine, which is what keeps the six component plans file-disjoint. What it costs is composability:
`stage-%` has no prerequisite chain, so `make stage-airflow` on a bare cluster fails at its first
missing dependency instead of building stages 10–55 first. That failure mode is recorded in a
comment beside the rule in the Makefile (an acceptance criterion of Task 2), so the limitation is
discoverable at the point of use rather than inferred from a stack trace. `make cluster-up` is the
only bootstrap entry point.
