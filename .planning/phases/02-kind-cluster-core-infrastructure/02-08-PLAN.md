<objective>
Close the sizing half of ROADMAP success criterion 5 and the remaining INFRA-07 and D-14 claims with
five static tests over the rendered manifests and the committed infrastructure tree: the CI profile
fits its runner, every container is sized, the two profiles diverge on named axes only, no script
performs manual `kubectl` surgery, and no credential or mutable image tag has leaked into a values
file.

Purpose: each of these is a claim the phase has been making since its first commit. Until a test
holds them, they are assertions. The sizing test in particular is the one that could most easily be
written to pass while measuring nothing — the research's prototype summed 0.35 cores across four
charts because the two PostgreSQL clusters are custom resources and not Pod templates.

Output: two new policy tests, one new detector, and two widened existing detectors — all static and
all sub-second. Four of the five sit inside the offline gate; the sizing module alone carries the
`manifests` marker, because it reads rendered output and must run after `make manifests` rather than
skip whenever it happens to run first.
</objective>

<user_story>
**As a** platform engineer,
**I want to** be told at pull-request time that my values change no longer fits the CI runner, left
a container unsized, opened a new divergence between the two profiles, or put a password in a file,
**so that** each of those becomes a red build in seconds rather than an eviction, a leaked
credential, or a CI-only bug discovered nine phases downstream.
</user_story>

## Planner note — three Wave 0 checks land here as retrofits

`02-VALIDATION.md` places `test_values_profiles.py`, `test_manifest_resources.py` and
`test_no_manual_kubectl_surgery.py` in Wave 0 — written before the artifacts they govern. They land

They are **retrofits**: they can report a defect but they cannot steer the authoring that produced
it. A values file written without limits, a fifth divergence axis, or an imperative `kubectl patch`
will be caught at wave 6 and fixed by an edit, not prevented at wave 1.

Two reasons this is nonetheless correct here rather than moved earlier. First, all three read
artifacts that do not exist until the waves that create them — a sizing test over rendered manifests
cannot precede the render pipeline, and a divergence-axis test needs both profiles of all five
components. Second, the Nyquist requirement is still satisfied by the plans that author those
artifacts: every values file carries a per-container resource acceptance criterion in its own plan
(02-01, 02-04, 02-06), every script's plan asserts its own idempotence and delegation, and D-06's
axis discipline is written into each values file's header comment as it is authored. This plan
converts those per-plan criteria into standing repository invariants; it is not the first time any
of them is checked. Moving these three earlier would fight the wave structure without changing when
the underlying property is first proved.
