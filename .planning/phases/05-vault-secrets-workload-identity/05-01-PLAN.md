<objective>
Deploy HashiCorp Vault into a new `vault` namespace as a persistent, non-dev-mode StatefulSet in both Helm values profiles, build the idempotent `hvac`-based admin bootstrap that creates its Kubernetes auth method, KV v2 mounts, both workload roles/policies (csv-processor final, airflow a documented best guess) and a persistent audit device, and prove -- on the live cluster -- that Vault's data survives a pod restart and that the scripted D-02 unseal procedure is what restores service.

Purpose: this is the foundation every later plan in this phase builds on. Without a running, persistent, unsealed, bootstrapped Vault, no workload identity can be tested and no credential can move out of a Kubernetes Secret. Deviation D3 (research SUMMARY.md) is why this lands now, after the slice, not before it -- and this plan is the first concrete piece of it.
Output: a live Vault instance reachable at `vault.vault.svc.cluster.local:8200`, unsealed via `make vault-unseal`, bootstrapped via `make vault-bootstrap`, with `make vault-verify` proving INFRA-06's restart-survival claim.
</objective>
