- `AIRFLOW__SECRETS__USE_CACHE` defaults to `False` (confirmed via Airflow's own `airflow.secrets.cache` module and search of official docs) -- this plan's Task 1 does not need to configure anything to make rotation work; Airflow's own Connection resolution is ALREADY a live, uncached Vault read on every lookup. Do not enable `AIRFLOW__SECRETS__USE_CACHE` anywhere in this task -- that would reintroduce rotation lag this plan exists to prove is absent.
- For the ETL-pod tier, "no restart required" would be trivially true (KPO pods are one-shot; there is no existing pod to demonstrate against) -- this is why the rotation proof targets Airflow's own long-running side (`minio_default`, resolved by whichever live Airflow process Plan 05-03 confirmed), not an ETL credential.
- Vault's audit log format (confirmed via official docs this session): top-level keys `type`, `time`, `auth`, `request`, `response`; sensitive string values are HMAC-SHA256 hashed by default (`hmac-sha256:...` prefix) -- never reason about or attempt to reverse this hashing; only assert the ABSENCE of the plaintext value substring, never attempt to validate the hash itself.
- `kubectl logs` is NOT in `tests/policy/test_no_manual_kubectl_surgery.py`'s permitted set (`get`, `wait` only) -- `scripts/vault-audit-tail.py` must read the PERSISTENT audit log FILE via `kubectl exec -i -n vault vault-0 -- tail ...`, never `kubectl logs vault-0`. Because this script is `.py`, not `.sh`, it is technically outside that policy test's scan regardless (see plan 05-01's T-05-08) -- but use the `exec -i`/persistent-file shape anyway, both because it is the correct, durable-across-restart design (05-RESEARCH.md Pitfall 2) and because it keeps the codebase's actual behavior consistent with its documented discipline even where a specific mechanical check does not reach.
- `scripts/ingest-demo.py`'s `_print_receipt()` (lines 599-614) is the exact "deliberately not raw JSON, human-facing" convention `vault-audit-tail.py`'s own output function must follow.
