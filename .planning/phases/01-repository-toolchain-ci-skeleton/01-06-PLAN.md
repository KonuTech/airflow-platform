  <action>
    Extend the generator with the byte-level capabilities the sixteen fixtures need, adding a
    manifest field for each so the capability is declarative rather than special-cased:

    Encoder selection with a strict error policy, so a character the declared encoding cannot
    represent fails generation loudly instead of being silently substituted.

    Byte-order-mark injection as raw bytes selected by the declared encoding, prepended after
    encoding — never delegated to a codec that decides for itself. Add a position field so a mark
    can be placed mid-stream, which is what a concatenated export looks like.

    Raw byte splicing: a manifest entry may declare byte sequences that are not valid text in the
    declared encoding, expressed as escaped literals in the manifest and spliced into the encoded
    output at a declared offset or after a declared record. This is what makes a truncated
    multibyte sequence expressible without committing a binary file.

    Per-record line terminators, so one file can mix terminators and another can use a bare
    carriage return throughout.

    Field-size parameterisation, so a single field can be declared longer than the standard
    parser's default limit.

    Multipart splitting: a wrapper kind that emits several numbered parts from one logical
    fixture, with the header in the first part only, and with all archive-style timestamps and
    embedded filenames zeroed the same way compression already is.

    Extend the manifest model with the matching fields and validators, keeping the outer schema
    closed. Every new field needs a validator that fails loudly on a nonsensical combination — a
    mark position beyond the file length, a spliced offset inside a multi-byte character boundary,
    a multipart split count below two.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Manifest escaped literals → generated bytes | Pathological byte sequences enter the tree through declaration, never through a committed binary |
| Generated corpus → git and Docker build contexts | Fixtures must remain untracked and excluded from build contexts |
| Corpus → secret scanner | Synthetic high-entropy values must not force a widened allowlist |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-29 | Tampering | Generator capability added, whole corpus re-baselined | high | mitigate | Per-fixture seed derivation means new capabilities change no existing byte; the acceptance criteria require a zero-deletion digest diff |
| T-01-30 | Repudiation | A fixture whose bytes no longer match its declared meaning | high | mitigate | `test_corpus_byte_level_fixtures.py` asserts semantics the digest cannot: mark offset, decodability, terminator mix, field limit, header placement |
| T-01-31 | Information Disclosure | Synthetic credential-shaped values in new fixtures | medium | mitigate | Any credential-shaped value carries the agreed synthetic prefix by construction; the scanner allowlist is path-and-prefix scoped and its self-test proves the scoping |
| T-01-32 | Tampering | Non-deterministic multipart or compressed output | high | mitigate | Archive timestamps and embedded filenames zeroed for every wrapper kind; verified by two consecutive generations producing an identical oracle |
| T-01-33 | Denial of Service | Oversized-field fixture aborting the whole parse | low | accept | Declared expectations state the outcome is a rejected record with a reason; the parser's limit is a contract parameter, set explicitly in Phase 6 |
</threat_model>
