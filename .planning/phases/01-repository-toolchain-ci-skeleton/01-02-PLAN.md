Make the secret gate real: full-history and working-tree scanning wired into CI, an allowlist
precise enough to stay honest, and a negative proof that the scanner actually fails a build.

and a scanner nobody has ever seen fail is indistinguishable from a disabled one. This plan
supplies both halves.
Output: `.gitleaks.toml`, a self-test that builds and scans a disposable repository, and the
`Secret scan (full history)` CI job.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Developer working tree → git history → public GitHub | Once the repository is public, any credential ever committed is world-readable and rotation is the only remedy |
| GitHub releases CDN → developer machine and CI runner | The scanner binary itself is downloaded and executed |
| Synthetic fixture corpus → secret scanner | High-entropy synthetic values pressure the team toward a global allowlist that would disable the control |
| CI job logs → anyone with repository read access | Scanner findings would otherwise carry the secret value into a permanent log |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-07 | Information Disclosure | git history | critical | mitigate | Full-history and working-tree scans in CI on a full-depth checkout; the scan must be green before publication (see plan 01-09's precondition) |
| T-01-08 | Repudiation | `.gitleaks.toml` allowlists | high | mitigate | Every allowlist scoped by path AND synthetic prefix; the self-test asserts a prefixed value outside the fixture tree is still reported, converting assumption A1 into evidence |
| T-01-09 | Tampering | gitleaks binary download | high | mitigate | Verify the published SHA-256 checksum before extraction; fail closed on mismatch; the version is pinned in one place and asserted against the workflow by plan 01-05 |
| T-01-10 | Information Disclosure | CI job logs | high | mitigate | Redaction on every scanner invocation; no `secrets.*` reference exists in this phase; plan 01-05 adds a policy test forbidding environment-dumping constructs in `run:` blocks |
| T-01-11 | Spoofing | A scanner that never fires | high | mitigate | The self-test builds a disposable repository with randomised-looking canaries and asserts a non-zero exit plus the expected rule identifiers — a configured-but-dead scanner fails this |
| T-01-12 | Tampering | Shallow checkout silently narrowing the scan | high | mitigate | `fetch-depth: 0` on the secrets job; plan 01-05's `test_secret_scan_depth.py` fails the build if it regresses |
</threat_model>
