    Write four records against the template.

    **0002 — `dataplat` core with `csv_processor` as a plugin.** This is the phase's headline
    departure: README §68 and §75 put a single package named for CSV at the root of the namespace.
    Cite ARCHITECTURE.md §4.1's six specific problems, and state the driver plainly — §29 and §95
    require adding non-CSV sources without redesign, and an architecture where a future Kafka CDC
    source imports through a CSV-named path violates that on day one. Record the considered
    options including the cheaper single-distribution variant with nested subpackages, and why the
    two-member split was chosen anyway. Its consequences section must name what Phase 10 inherits:
    CDC and SCD modules live in the core, not under the CSV plugin. Migration trigger: none
    foreseen; a reversal would be a rename across every module and every DAG.

    **0003 — workspace members under `packages/`, not `src/`.** Small but visible: it departs from
    ARCHITECTURE.md's own diagram. The reason is mechanical — a workspace member is a directory
    containing its own project file, so keeping a single root source directory while giving each
    member its own project file produces a doubled path. Source layout is preserved *inside* each
    member, which is what the original rationale actually requires. Two paragraphs is the right
    length.

    **0004 — two images, two dependency sets.** The Airflow distribution is deliberately not a
    workspace member: a workspace resolves one lockfile for all members, so Airflow's constraint
    pins would silently become the ETL library's constraints. The decision is *made* in this phase
    by keeping it out of the workspace; recording it here means the Phase 4 Dockerfile author does
    not re-derive it. Include the Docker consequence RESEARCH.md notes: the build must resolve
    dependencies without installing workspace members first, then switch once the members are
    copied.

    **0005 — the fixture corpus is generated from a seed, not committed.** The determinism rules
    need a home that is not a test docstring. Record all ten rules by name and mechanism, the
    committed-oracle pattern, and the two things the decision buys that a committed corpus cannot:
    a size-parameterised large fixture, and a secret scanner that is not drowned by thousands of
    synthetic files. Migration trigger: if generation time ever exceeds the pull-request budget —
    with the measured figures showing how much headroom exists.

    Update the index table in `docs/adr/README.md` with all five records.
