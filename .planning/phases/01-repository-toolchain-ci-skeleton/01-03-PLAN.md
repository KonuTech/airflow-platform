<objective>
Build the corpus machinery: a validated manifest, a deterministic generator, a committed digest
oracle, and the tests that keep all three honest. Then seed the manifest with five fixtures that
exercise every generator kind, so the framework is proven before plans 01-06, 01-07 and 01-08
author the remaining sixty-four.

Purpose: the corpus is the specification for the CSV engine. If its bytes are not reproducible,
every downstream detector test silently re-baselines and the specification stops being one.
Output: `tools/corpus/`, `tests/fixtures/corpus.yaml`, `tests/fixtures/CORPUS.sha256`, and
`fixtures-verify` wired into `make check`.

  <action>
    Write `tools/corpus/generators.py` implementing four generator kinds against the manifest
    model: `tabular` (header plus parameterised rows), `literal` (bytes declared in the manifest
    as escaped literals), `literal_unicode` (rows whose fields carry an explicit normalisation
    form), and `wrapper` (compresses or splits an already-declared fixture).

    Implement determinism rules R1 through R10 exactly as RESEARCH.md states them, because each
    one defeats a specific named mechanism:

    R1 — derive each fixture's random stream from a digest of the master seed joined with the
    fixture name, never from one shared stream, so inserting a fixture changes exactly one digest
    line instead of every later one.
    R2 — consume randomness only through the two methods CPython documents as stable across
    versions; derive integers and selections by arithmetic over those. RESEARCH.md rule R2 names
    the convenience helpers whose algorithms are explicitly allowed to change between Python
    releases; task 3's policy test enforces their absence.
    R3 — build a string, encode it to the declared encoding, and write in binary mode. Never open
    a fixture in text mode, where the platform's preferred encoding leaks in.
    R4 — join lines with the manifest's declared terminator by hand; never let a writer choose one.
    R5 — zero the embedded timestamp and clear the embedded source filename on every compressed
    fixture, and set an explicit fixed date on every archive entry. Two runs a second apart
    otherwise produce different bytes, which RESEARCH.md measured.
    R6 — no wall-clock, process-identity or OS-entropy call anywhere under `tools/corpus/`.
    R7 — iterate the manifest in declared order; never iterate an unordered collection, because
    string hashing is process-salted.
    R8 — never read directory listing order as generation input.
    R9 — build normalisation variants with explicit normalisation calls, never by pasting two
    visually identical strings into the source, which editors and git filters silently collapse.
    R10 — format numbers with explicit format strings or exact decimal arithmetic.

    Write a comment at the top of the module stating that the reproducible pseudo-random
    generator is the correct choice here and the cryptographic one is not, so nobody "fixes" it.

    Write `tools/corpus/digests.py` producing standard `sha256sum`-format lines, and
    `tools/corpus/__main__.py` exposing `generate` and `verify`. `generate` materialises the
    corpus and rewrites the oracle; `verify` regenerates into a temporary directory and compares
    against the committed oracle without touching it. That asymmetry is what makes a generator
    change a reviewable diff instead of a silent re-baseline. Support a fast switch that skips
    the large profile for the inner development loop, while `make check` and CI always run the
    full set — a fast path that is also the default is a fast path that stops testing the thing.

    Seed `tests/fixtures/corpus.yaml` with exactly five fixtures, chosen so every generator kind
    and the large profile are exercised now and none is re-authored later: `01_simple.csv`
    (tabular), `29_large_file.csv` (tabular, large profile, with the size and address-space knobs),
    `32_nul_bytes.csv` (literal), `44_unicode_nfc_vs_nfd.csv` (literal_unicode) and
    `61_gzipped.csv.gz` (wrapper over `01_simple.csv`). Copy their declarations from RESEARCH.md's
    worked entries, including the `expect:` blocks.

    One correction to carry: `32_nul_bytes.csv` must expect a validation outcome, not a parser
    exception. RESEARCH.md verified on CPython 3.12.3 that the standard CSV reader parses an
    embedded NUL without error and the value survives inside the field; the failure is downstream,
    where PostgreSQL text types cannot store it. Its `expect:` block therefore declares a
    quarantine reason and states that the parser does not raise. FEATURES.md says the opposite
    and is wrong.

    Generate the corpus, commit `CORPUS.sha256`, and extend the Makefile's `check` chain with
    `fixtures-verify` — the one Makefile edit this plan makes.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `tests/fixtures/corpus.yaml` → generator process | The manifest is the only untrusted input this phase deserialises |
| Generator output → repository / build contexts | Generated bytes must never enter git or a Docker build context |
| Synthetic corpus → secret scanner | High-entropy synthetic values must not force a global allowlist |
| Generator source → future maintainers | A well-meaning edit can silently destroy reproducibility with no failing test |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-13 | Elevation of Privilege | YAML deserialisation of the manifest | high | mitigate | Safe loader only, into a frozen model that forbids unknown keys at the outer level; asserted by task 1's tests |
| T-01-14 | Tampering | Corpus bytes drifting from the specification | high | mitigate | Committed digest oracle in standard format; `fixtures-verify` regenerates into a temporary directory and only ever reads the oracle, so a generator change is a reviewable diff |
| T-01-15 | Repudiation | Determinism rules eroding silently | high | mitigate | `test_generator_determinism_rules.py` enforces rules R2 and R6 by source inspection and R1 by observable consequence |
| T-01-16 | Information Disclosure | Synthetic credential-shaped values in fixtures | medium | mitigate | Every synthetic credential-shaped value carries the agreed prefix by construction; plan 01-02's allowlist is scoped to the fixture tree and its self-test proves the scoping holds |
| T-01-17 | Denial of Service | 241 MB fixture in every gate run | low | accept | Measured at roughly four seconds to generate and a tenth of a second to hash; a cache would add a staleness hole to the one artifact whose purpose is reproducibility |
| T-01-18 | Tampering | Generated fixtures entering a Docker build context | medium | mitigate | `.dockerignore` written in plan 01-01 excludes the test tree; `test_corpus_not_committed.py` keeps them out of git |
</threat_model>
