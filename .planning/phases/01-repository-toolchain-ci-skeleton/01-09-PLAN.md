## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Repository settings → the enforcement of every gate in this phase | Without a branch rule, every control built here is advisory |
| Local git → public GitHub | Publication is irreversible; anything in the history is world-readable from that moment |
| Workflow job names → required check names | A rename silently un-requires a check, leaving a rule that blocks nothing |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-43 | Elevation of Privilege | Merging past a failing gate | high | mitigate | Required status checks on the default branch with strict mode, plus a required pull request; read back through the API and confirmed by a human on a deliberately-failing pull request |
| T-01-44 | Information Disclosure | Publication of a history containing a credential | critical | mitigate | The full-history scan being green is this plan's precondition; publication is the irreversible step and the scan is its gate |
| T-01-45 | Tampering | Force push or branch deletion erasing gated history | high | mitigate | Force pushes and deletions disallowed on the default branch by the same rule |
| T-01-46 | Spoofing | A required check name that matches nothing | high | mitigate | Names are read from the repository's reported checks, not guessed from the workflow file; the read-back asserts membership rather than rule existence; the coupling is documented as the rot path |
