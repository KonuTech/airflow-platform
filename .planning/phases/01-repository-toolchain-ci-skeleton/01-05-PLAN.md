    every repository-secret reference across all workflow files is in an allowed set which, in
    this phase, is empty; the test must state that the set is expected to grow in Phase 11 and
    that an addition obliges a re-audit. Second, every scanner invocation in the Makefile carries
    redaction, so a finding never reaches a log with its value intact. Third, no run block
    contains an environment-dumping construct — shell tracing, a bare environment print, or a
    variable dump.

    of "no CI job ever echoes a secret" is undecidable, because a future step passing a token to a
    verbose network client leaks through output that matches no pattern. What is decidable, and is
    fully true in this phase, is the stronger structural claim that the workflow references no
    secret at all. That framing is what the phase asserts, and it is what must be revisited the
    first time a secret is introduced.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Repository configuration → the gate's actual strength | A one-line configuration edit can disable a control while leaving every green check green |
| Workflow definition → the gate that runs on a pull request | CI can silently run a subset of the local gate |
| Bad-sample directory → the main lint and type runs | Deliberately-broken files that are not excluded make the gate permanently red and invite deleting the samples |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-23 | Spoofing | A configured-but-dead gate | high | mitigate | `test_gates_actually_fail.py` runs each real tool against a bad sample and asserts the exit status and the rule identity, paired with a good-sample positive control |
| T-01-24 | Tampering | Gate weakened by a configuration edit | high | mitigate | `test_print_ban_scope.py` and `test_pinned_tool_versions_agree.py` fail on a narrowed rule scope or a version drift on either side |
| T-01-25 | Repudiation | CI running a different gate than local | high | mitigate | `test_ci_invokes_make_only.py` plus `test_ci_calls_make_ci.py` assert the workflow delegates and that the CI target is a superset of the local one |
| T-01-26 | Information Disclosure | Secret reaching a CI log | high | mitigate | `test_workflow_secrets.py` enforces the empty secret set, mandatory redaction, and the absence of environment-dumping constructs; the undecidable residue is documented, not claimed |
| T-01-27 | Tampering | Secret scan narrowed to one commit | high | mitigate | `test_secret_scan_depth.py` asserts full-history checkout on the parsed workflow |
| T-01-28 | Denial of Service | Bad samples breaking the main gate | low | mitigate | Lint and type exclusions verified in force before the samples are written; the acceptance criteria require observing the failure when the exclusion is removed |
</threat_model>
