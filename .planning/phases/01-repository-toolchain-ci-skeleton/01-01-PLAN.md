<objective>
Prove the whole delivery pipeline end to end on the thinnest possible path: one real typed,
documented function in `dataplat`, one unit test, one policy test, one Makefile that defines
the gate, and one GitHub Actions job that calls it. This is Phase 1's walking skeleton — the
data-pipeline skeleton belongs to Phase 4 (see `SKELETON.md`).

**Phase goal (verbatim from ROADMAP.md, not restated as a user story — the Goal line is not in
user-story form and this planner does not invent one):** *Every future commit is gated by lint,
type checking, unit tests and secret scanning, and the CSV fixture corpus that specifies the
engine is reproducible from a seed.*

Purpose: every later plan in this phase, and every commit in the ten phases after it, lands on
top of this gate. Building it first is deviation D4 — a pipeline created in the final phase
cannot have gated any earlier code.
Output: a uv workspace with two members, a Makefile that is the single definition of every
check, and a CI workflow whose only substantive step is `make check`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PyPI / Astral CDN → developer machine and CI runner | Third-party package and installer bytes cross into the build |
| GitHub Actions marketplace → CI runner | Third-party action code executes with repository context |
| Fork pull request → CI runner | Untrusted contributor code triggers a workflow run |
| Developer working tree → git history | Anything committed is permanent and, once the repo is public, world-readable |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | `.github/workflows/ci.yml` action references | high | mitigate | Pin `actions/checkout` and `astral-sh/setup-uv` by 40-char commit SHA, not tag; asserted by the acceptance criteria and by plan 01-05's policy test |
| T-01-02 | Elevation of Privilege | CI trigger for fork PRs | high | mitigate | Use the `pull_request` trigger (secrets are not exposed to fork runs) with workflow-level `permissions: contents: read`; no job elevates |
