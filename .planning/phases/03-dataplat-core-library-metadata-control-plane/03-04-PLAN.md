<objective>
Build the config-not-code system SCHEMA-07 requires: a Pydantic `DatasetConfig` model
(`extra="forbid"`, `frozen=True`), a canonical-JSON sha256 hash recipe, a loader merging
per-dataset YAML over platform defaults, and `ConfigRegistry` — the Postgres-backed system of
record for `meta.config_versions`, implementing ARCHITECTURE.md §5.1's hash-compare-and-version
logic. Seeds the one real dataset config this phase needs: `configs/datasets/customers.yaml`.

Purpose: SCHEMA-07 requires every run to record which config version produced it — this plan makes
"config version" a real, hashed, versioned row rather than a filename.

Output: `dataplat/config/{model,loader,hashing,registry}.py`, `configs/defaults.yaml`,
`configs/datasets/customers.yaml`, `schemas/dataset-config.schema.json`, and the tests proving
canonicalization and the sync round trip.
</objective>

<user_story>
**As a** developer adding a new dataset to the platform,
**I want to** write one YAML file, have it validated against a typed schema and hashed
deterministically, and see it land as a versioned row in `meta.config_versions` the moment it
syncs,
**so that** adding a dataset is zero new Python, and any later run can answer "which config
version produced this row" by one SQL join.
</user_story>
