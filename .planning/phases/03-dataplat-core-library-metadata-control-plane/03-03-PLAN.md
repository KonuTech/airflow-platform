<objective>
Build the two cross-cutting subsystems every later stage and the CLI import from day one:
real structured logging (JSON in-cluster, console locally, contextual fields, secret redaction)
and the `SecretsResolver`'s `env://`/`file://` half. Both are self-contained aside from
`dataplat.errors` (plan 03-01); nothing here talks to Postgres, MinIO or a live pipeline.

Purpose: OBS-02/04/05 are not optional or seam-only — success criterion 5 requires them directly,
and SEC-15 is what makes deviation D3 (Vault arriving in Phase 5 as a configuration change, not a
redesign) safe. The redaction processor and the resolver are tested together in this plan because
their correctness is only meaningful as a pair: a resolver that never leaks a value into a log
line is the actual guarantee, not two independently-plausible pieces.

Output: `dataplat/observability/{logging,metrics,tracing}.py`, `dataplat/secrets/resolver.py`,
and the three unit test files proving OBS-02/04/05 and SEC-15.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| resolved secret value → structlog event dict | the point where a credential enters the logging pipeline; redaction must occur before the renderer, not after |
| environment / filesystem → `resolve_secret()` | the resolver trusts its two backends completely; an attacker who controls an env var name or a file path the caller resolves controls the returned value — that trust boundary is the caller's responsibility (SEC-15's `env://`/`file://` refs are themselves already-authorized configuration, not untrusted input) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | `dataplat.secrets.resolver.resolve_secret` | mitigate | Fails closed on any scheme other than `env://`/`file://`, including `vault://`; never returns an unresolved reference string; Task 2 Test 5/6 assert this |
| T-03-02 | Information Disclosure | `dataplat.observability.logging` processor chain | mitigate | `_redact` runs before the renderer for every configured logger; secret-pattern keys are replaced, not merely masked partially; Task 3 proves the pair end to end and structurally asserts chain ordering |
| T-03-09 | Tampering | `resolve_secret()` given a `file://` path outside the intended secrets mount | accept | This phase only proves the mechanism against arbitrary local paths (testcontainers-only scope); path allow-listing is a Phase 5/Vault-adjacent concern once real pod mount paths exist |
</threat_model>
