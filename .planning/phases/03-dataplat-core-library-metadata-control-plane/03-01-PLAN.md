<objective>
Lay the one foundation every other Phase 3 plan builds on: the QUAL-03 exception hierarchy, the
frozen value objects that make errors-as-values possible, and the one psycopg connection-pool
factory the rest of the phase reuses instead of each reinventing pool construction. Nothing in
this plan talks to a real database or object store — it is pure, dependency-light Python that
Wave 2's config, storage and metadata plans import.

Purpose: ARCHITECTURE.md §4.5 and CONTEXT.md D-06 both treat the exception hierarchy and the
row-level error vocabulary (`RejectedRecord`, `StageResult`) as the single most load-bearing
contract in the library — every later stage's "never silently discard a record" guarantee is
mechanical only if these types exist first and are used consistently from the first commit.

Output: `dataplat/errors.py`, `dataplat/models/{identity,record,report}.py`,
`dataplat/storage/db.py`, and `packages/dataplat/pyproject.toml` carrying dataplat's first real
runtime dependencies (`psycopg[binary,pool]`, `boto3`, `pydantic`, `structlog`, `click`).
</objective>
