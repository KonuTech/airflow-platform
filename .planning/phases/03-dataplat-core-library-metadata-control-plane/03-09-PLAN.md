<objective>
Close the sole UAT gap from 03-UAT.md: `tests/integration/test_metadata_repository.py` fails with
`psycopg.errors.UniqueViolation` on `uq_config_versions_dataset_version` when the whole
`tests/integration/` directory runs together in one pytest session (as `make test-integration` and
CI's `integration` job actually run it) — the exact scenario Wave 3's isolated per-plan test runs
(03-04, 03-05) never exercised.

Root cause (03-UAT.md, diagnosed): both `test_config_registry.py` (03-04) and
`test_metadata_repository.py` (03-05) independently create a dataset literally named `"customers"`
against the same session-scoped Postgres fixture (`tests/integration/conftest.py`). pytest's default
alphabetical file collection always runs `test_config_registry.py` first, so it deterministically
creates `(dataset_id=1, version=1)` in `meta.config_versions` before
`test_metadata_repository.py::_insert_config_version()` runs — which hardcodes `version=1` with no
conflict handling and always collides with the pre-existing row.

`get_or_create_dataset()` itself is correct (idempotent `ON CONFLICT DO UPDATE`) and needs no change —
this is purely a test-isolation bug in `test_metadata_repository.py`.

Purpose: Restore the observable truth "make test-integration passes cleanly when the whole
tests/integration/ directory runs together in one pytest session" (03-UAT.md test 1), which is the
literal way `make test-integration` and CI's `integration` job invoke the suite.
Output: `tests/integration/test_metadata_repository.py` collision-free against any other file sharing
the session-scoped fixture, present or future.
</objective>
