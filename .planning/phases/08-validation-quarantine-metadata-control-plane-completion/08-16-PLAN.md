<objective>
Close the VALID-08 gap-closure architecture decision at its schema/contract root: give `meta.rejected_records` a durable `business_key` column, and replace the strictly-`batch_id`-scoped resolution write path with a `(dataset_id, business_key)`-scoped one, per the LOCKED decisions D-23/D-24/D-25 in `08-CONTEXT.md`'s "Gap closure: VALID-08 backfill resolution scoping" section.

08-VERIFICATION.md's live-confirmed root cause: `discover_files`'s `batch_key` is a pure function of a file's `content_sha256`, so a content-differing correction of a previously-rejected row always discovers under a NEW `batch_id`. `resolve_rejected_records_for_batch` (the current mechanism) scopes strictly by `batch_id`, so it can never touch the ORIGINAL batch's `PENDING` row — the "documented re-drive path" half of Truth #3 (Phase 8's roadmap success criterion 3) is confirmed broken by this architecture mismatch, not by a bug in any single file.

This plan lays the contract-first foundation (interface-first ordering, per this codebase's own established pattern of Protocol-then-implementation): the DB column, the `RejectedRecord` model field, and the `MetadataRepository` Protocol + `PostgresMetadataRepository` implementation of the new resolution write path. Plans 08-17 (business-key extraction at every `RejectedRecord`-creation site) and 08-18 (wiring the new resolution call into `run_ingest` + the live-cluster proof) build on top of what this plan establishes.

Purpose: make the resolution *matching predicate* durable across a content-differing file's necessarily-new `batch_id`, per D-23 ("extend that same identity concept [business-key-driven publish] to rejection resolution instead of inventing a second, batch-lineage-based identity scheme"), while preserving D-24's whole-set-side-effect-only granularity and D-25's NULL-business-key-never-auto-resolves fallback.
Output: `meta.rejected_records.business_key` column (migration 0020), `RejectedRecord.business_key` field, `MetadataRepository.resolve_rejected_records_for_business_keys` (replacing `resolve_rejected_records_for_batch`), and a rewritten `tests/integration/test_backfill_resolution.py` proving the new scoping rules in isolation.
</objective>
