## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| kubectl exec `ls /data` on the MinIO pod | The MinIO chart mounts the PVC at `/export`, not `/data`. Checking `/data` shows an empty, recently-created directory that looks like data loss but is actually just the wrong path — wasted significant time diagnosing a phantom "MinIO wiped its data" bug this session. | advisory | Always check `kubectl get pod -n data <minio-pod> -o jsonpath='{.spec.containers[0].volumeMounts}'` first, or just use `/export` directly. |
| Directly UPDATE-ing Airflow's `dag_run`/`task_instance` tables via psql to force a stuck run to a terminal state | Blocked by the permission classifier, correctly — this bypasses Airflow's internal consistency (executor state, XCom, etc.). | blocking | Use the Airflow REST API instead: `POST /auth/token` with `{"username":"admin","password":"admin"}` to get a bearer token (admin/admin is this cluster's default UI login), then `PATCH /api/v2/dags/{dag_id}/dagRuns/{dag_run_id}` with `{"state":"failed"}`. Port-forward `svc/airflow-api-server` to reach it from the host. |
| Backgrounding `kubectl port-forward` across multiple Bash tool calls | The forwarded process sometimes dies silently between tool-call boundaries in this harness (observed multiple times this session — process shows as running via `ps aux` from one call but "Connection refused" on the very next call). | advisory | Before any DB/API operation via a port-forward, re-verify with `nc -z localhost <port>` in the SAME tool call as the operation, not a prior one. If dead, kill and restart fresh. |

**Severity values:** `blocking` — resuming agent must pass understanding check before proceeding. `advisory` — important context, does not gate resumption.
