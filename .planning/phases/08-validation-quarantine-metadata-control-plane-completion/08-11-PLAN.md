<objective>
Wire every barrier stage built in Wave 3 (`ReferentialIntegrityBarrier`, `RejectionRateCircuitBreaker`, `VolumeAnomalyBarrier`) and every streaming-rule rejection accumulated during Wave 4's staging pass into `run_ingest`'s existing publish transaction — the single load-bearing point where D-11's "nothing publishes on FAIL" guarantee is either true or merely aspirational. This is the phase's most consequential wiring task: every prior plan's isolated, unit-tested logic becomes one real, atomic run outcome here.

Purpose: this plan is what turns VALID-01 through VALID-04, VALID-07 and VALID-09 from "isolated classes with passing unit tests" into "an actual property of a real ingestion run." Pitfall 2 (RESEARCH.md) — persisting validation/rejection rows outside the publish transaction — is the single specific failure mode this plan exists to avoid.
Output: `StagingLoader.load()` now returns the actual `RejectedRecord` list (not just a count); `run_ingest` runs the referential barrier (excluding orphans from what publishes), the circuit breaker (raising `QualityThresholdExceeded` on breach, inside the transaction), and the volume-anomaly barrier, then persists every `ValidationResult`/`RejectedRecord` via the SAME `conn` `Publisher.publish()` used — all before the transaction's `with` block exits; `customers.yaml` gains a real `quality:` block (D-09); `Receipt` gains a `rows_quarantined` field.
</objective>
