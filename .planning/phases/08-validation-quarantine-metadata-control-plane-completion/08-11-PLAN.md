<objective>
Wire every barrier stage built in Wave 3 (`ReferentialIntegrityBarrier`, `RejectionRateCircuitBreaker`, `VolumeAnomalyBarrier`) and every streaming-rule rejection accumulated during Wave 4's staging pass into `run_ingest`'s existing publish transaction -- the single load-bearing point where D-11's "nothing publishes on FAIL" guarantee is either true or merely aspirational. Additionally, and just as load-bearing: this is the ONE place D-05's backfill-resolution mechanism (plan 08-03's `resolve_rejected_records_for_batch`, stubbed in plan 08-01, implemented and unit-tested in isolation in plan 08-03) actually gets called by a real ingestion run. Without this plan's Task 1 calling it, `resolve_rejected_records_for_batch` is dead code that only its own integration test ever invokes -- this plan is what makes D-05 a genuine property of a real backfill, not an isolated, unreachable method.

Purpose: this plan is what turns VALID-01 through VALID-04, VALID-07 and VALID-09 from "isolated classes with passing unit tests" into "an actual property of a real ingestion run," AND what turns D-05's "rejected_records rows get marked resolved and linked to the new run_id" from a documented intention into a real, reachable code path. Pitfall 2 (RESEARCH.md) -- persisting validation/rejection rows outside the publish transaction -- is one specific failure mode this plan exists to avoid; an un-called `resolve_rejected_records_for_batch` is the other.
Output: `StagingLoader.load()` now returns the actual `RejectedRecord` list (not just a count); `run_ingest` runs the referential barrier (excluding orphans from what publishes), the circuit breaker (raising `QualityThresholdExceeded` on breach, inside the transaction), and the volume-anomaly barrier, then persists every `ValidationResult`/`RejectedRecord` via the SAME `conn` `Publisher.publish()` used, THEN calls `resolve_rejected_records_for_batch` for this run's own `batch_id` -- all before the transaction's `with` block exits; `customers.yaml` gains a real `quality:` block (D-09); `Receipt` gains a `rows_quarantined` field.
</objective>
