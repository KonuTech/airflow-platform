`validate/volume_anomaly.py`: `VolumeAnomalyBarrier(BarrierStage)`, `name = "volume_anomaly_barrier"`. `__init__(self, *, ctx_db_query: Callable[[], tuple[float | None, int]] | None = None, dataset_id: int, current_row_count: int, multiplier: float, rule_id: str, strategy: str) -> None` — the historical-average lookup is a SQL query this stage issues itself inside `apply()` against `ctx.db` (a `ConnectionPool`), not a value passed in, since the whole point is a fresh, per-run comparison against currently-persisted history: `SELECT AVG(evaluated_count), COUNT(*) FROM meta.validation_results vr JOIN meta.ingestion_runs ir ON vr.run_id = ir.run_id WHERE ir.dataset_id = %s AND vr.rule_type = 'VOLUME' AND ir.status = 'SUCCEEDED'` (bind `dataset_id`; `evaluated_count` on a prior `VOLUME` row IS that prior run's own row count, by this same class's own writing convention below — self-referential by design, matching how a moving average is meant to work). `apply(self, ctx: PipelineContext) -> StageResult`: opens `ctx.db.connection()`, runs the query above, fetches `(historical_average, prior_run_count)`. If `prior_run_count < 2` (cold start — the resolved-guidance minimal case, not a full historical-trend model), return `PASS` with `observed={"historical_average": None, "prior_run_count": prior_run_count}`, `failed_count=0`. Else if `self._current_row_count > historical_average * self._multiplier`, return the configured `strategy`-mapped `outcome` (`"QUARANTINE"` for `QUARANTINE_FILE`/`QUARANTINE_RECORD`, `"FAIL"` for `FAIL_FILE`, `"PASS_WITH_WARNING"` for `WARN_AND_CONTINUE` — a small local dict mapping `strategy` to `outcome`, matching D-07's per-rule-type-strategy framing) with `observed={"current_row_count": self._current_row_count, "historical_average": historical_average, "multiplier": self._multiplier}`, `failed_count=1`, `evaluated_count=self._current_row_count`. Else `PASS`. Every `ValidationResult` this stage returns has `rule_type="VOLUME"` — this is BOTH the anomaly-comparison output AND, via `evaluated_count=self._current_row_count`, the exact row this run's own persisted history contributes for a LATER run's comparison (the "persist a row_count metric per run" half of the resolved scope — no separate write path needed; the SAME `meta.validation_results` row this barrier's `findings` entry produces, once persisted by plan 08-11's wiring, IS next run's history).
