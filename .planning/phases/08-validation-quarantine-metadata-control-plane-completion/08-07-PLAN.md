`validate/circuit_breaker.py`: `RejectionRateCircuitBreaker(BarrierStage)`, `name = "rejection_rate_circuit_breaker"`. `__init__(self, *, threshold: float, rule_id: str = "rejection_rate_circuit_breaker") -> None` stores `threshold`/`rule_id`. This stage does NOT itself count rows — it needs the run's own totals, which only `ctx` (via a field this plan's constructor accepts, or a value the caller passes) can supply; since `BarrierStage.apply(self, ctx: PipelineContext) -> StageResult` takes no other parameter per the existing Protocol, and this stage's totals come from the run's OWN staging result (not yet known to the Protocol), construct this stage with the totals ALREADY known at construction time rather than trying to read them from `ctx` — i.e. `__init__(self, *, threshold: float, total_rows_read: int, total_rows_rejected: int, rule_id: str = "rejection_rate_circuit_breaker") -> None`, and `apply(self, ctx: PipelineContext) -> StageResult` computes the ratio from those stored values (never re-derives them from `ctx`, which has no row-count field). Document this constructor shape explicitly: the CALLER (plan 08-11's `pipeline/run.py` wiring) constructs a fresh `RejectionRateCircuitBreaker` per run, after `StagingLoader.load()` has already returned `StagingResult.rows_read`/`.rows_rejected` — this stage is a pure, already-parameterized threshold check, not a stateful accumulator. `apply()`: if `total_rows_read == 0`, return a trivial PASS `StageResult` immediately (no breach possible). Else compute `ratio = total_rows_rejected / total_rows_read`; if `ratio > self._threshold`, raise `QualityThresholdExceeded(f"rejection rate {ratio:.2%} exceeds configured threshold {self._threshold:.2%}", context={"rule_id": self._rule_id, "observed_ratio": ratio, "threshold": self._threshold, "total_rows_read": total_rows_read, "total_rows_rejected": total_rows_rejected})`. Otherwise return `StageResult(chunk=<a placeholder empty-rows RecordChunk, since this barrier owns no chunk of its own>, rejected=[], findings=[ValidationResult(rule_id=self._rule_id, rule_type="QUALITY", severity="ERROR", outcome="PASS", evaluated_count=total_rows_read, failed_count=total_rows_rejected, message="rejection rate within threshold", threshold={"rejection_rate_threshold": self._threshold}, observed={"ratio": ratio})])`.

Add `"CIRCUIT_BREAKER": RejectionRateCircuitBreaker` to `VALIDATION_RULE_REGISTRY` (dataset-wide, no `column`).

  </behavior>

`validate/uniqueness.py`: `UniquenessRule(StreamingStage)`, `name = "uniqueness_rule"`. `__init__(self, *, column_index: int, column_name: str, strategy: str, rule_id: str) -> None`. `apply(self, ctx, chunk) -> StageResult`: iterate rows, maintain a local `set[object]` of already-seen values at `column_index` (freshly empty at the start of every `apply()` call — never persisted across calls, which is what makes this within-chunk-scoped, not cross-chunk); a row whose value is already in the set is rejected (`error_type="UNIQUENESS_VIOLATION"`, `error_message` naming the duplicate value and column); otherwise add the value to the set and keep the row.
