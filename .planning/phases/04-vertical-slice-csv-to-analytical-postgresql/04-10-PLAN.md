<objective>
Close CR-01 and CR-02 from `04-REVIEW.md` -- the two Critical findings VERIFICATION.md elevated to FAILED truths (#7 and #8) -- plus the live, already-manifested data consequence of CR-02.

CR-01: `pipeline/run.py`'s `_heartbeat_loop` writes `status="RUNNING"` unconditionally on every tick, with no guard against the run having already reached a terminal status. A tick landing in the narrow window between the publish transaction's commit and `stop_heartbeat.set()` (in `run_ingest`'s `finally` block) silently regresses a genuinely-`SUCCEEDED` run back to `RUNNING`, at which point `claim_ingestion_run`'s reclaim predicate can pick it up and fully re-execute it, corrupting `rows_loaded`/`duration_ms` audit history for a run that actually succeeded.

CR-02: `metadata/postgres.py`'s `find_file_by_content_hash` is `SELECT file_id FROM meta.files WHERE dataset_id = %s AND content_sha256 = %s LIMIT 1` with no `ORDER BY` -- PostgreSQL documents this as unspecified once 2+ rows match. `discovery.py`'s rediscovery-correction logic depends on this call returning the same row across calls for the same content; that assumption has already broken live -- `meta.files.file_id=10` is currently orphaned in the running cluster (`duplicate_of_file_id IS NULL`, `status='DISCOVERED'`, zero `meta.ingestion_runs` rows reference it), even though its content is a byte-identical duplicate of an already-`SUCCEEDED` file.

Purpose: both findings directly undermine this platform's own Core Value ("every file, batch and record... can be traced, explained, reprocessed and trusted") -- CR-01 threatens the run-lifecycle audit trail's integrity, CR-02 has already broken the file-lineage-by-SQL-alone guarantee (ROADMAP Success Criterion 4 / LOAD-04) for one real row.
Output: `heartbeat_ingestion_run`, a terminal-status-safe replacement for the heartbeat's write target; a deterministic `find_file_by_content_hash`; and a one-off, idempotent, generic repair of the live cluster's already-orphaned row(s), applied only after the code fix is built into the image the cluster will run next.
</objective>

    self,

    dataset_id: int,
    content_sha256: bytes,
) -> int | None:
    """See `MetadataRepository.find_file_by_content_hash`."""
