<objective>
Close WR-01 from `04-REVIEW.md`: `csv_processor.cli.ingest()`'s own docstring promises a `Receipt` is written to the XCom path "on every exit path, success or failure," but the implementation only ever catches `DataPlatformError`. Any other exception class -- a raw `psycopg.errors.DataError` from a publish-time cast failure (WR-04, out of scope here), a network error, `MemoryError`, or anything else outside the `DataPlatformError` hierarchy -- propagates with no Receipt ever written, contradicting the function's own stated contract.

Purpose: a written Receipt on every exit path is this platform's own auditability guarantee (META-03's spirit, per VERIFICATION.md's Requirements Coverage note on this exact finding). Airflow still fails the task via the pod's non-zero exit code either way, so this is not a data-loss bug -- but it is a confirmed, literal contract violation this phase's own plan (04-05) committed to and VERIFICATION.md elevated to a FAILED truth (#6).
Output: `ingest()`'s exception handling broadened to guarantee a written Receipt for any exception, plus the first dedicated unit-test file for `csv_processor.cli`.
</objective>

From `packages/csv-processor/src/csv_processor/cli.py` (current, `ingest()`'s try/except -- the contract violation):
```python
@cli.command()
@click.option("--assignment", required=True, help="The s3://bucket/key URI of the assignment JSON.")
def ingest(assignment: str) -> None:
    """... A `Receipt` is written to the XCom path on every exit path, success or
    failure -- the `finally`/`except` pairing below is this command's own
    concern ...
    """
    pool: ConnectionPool | None = None
    doc: AssignmentDocument | None = None
    try:
        pool, metadata, objects = _build_common()
        bucket, key = _parse_s3_uri(assignment)
        with objects.get_object(bucket, key) as stream:
            raw_text = stream.read()
        try:
            doc = AssignmentDocument.model_validate_json(raw_text)
        except ValidationError as exc:
            msg = f"invalid assignment document at {assignment}"
            raise ConfigurationError(msg, context={"assignment": assignment}) from exc
        config = ConfigRegistry(pool).get_by_id(doc.config_version_id)
        source_bucket, source_key = _parse_s3_uri(doc.file.object_uri)
        run = RunContext(
            run_id=doc.run_id,
            idempotency_key=doc.idempotency_key,
            attempt=int(os.environ.get("AIRFLOW_TASK_TRY_NUMBER", "1")),
            file_id=doc.file.file_id,
            batch_id=doc.batch.batch_id,
        )
        ctx = PipelineContext(run=run, config=config, metadata=metadata, objects=objects,
                               db=pool, log=get_logger(), source=CsvSource(bucket=source_bucket, key=source_key))
        heartbeat_interval_seconds = float(os.environ.get("DATAPLAT_HEARTBEAT_INTERVAL_SECONDS", "60.0"))
        receipt = run_ingest(ctx, heartbeat_interval_seconds=heartbeat_interval_seconds)
        _write_xcom(receipt)
    except DataPlatformError:
        _write_xcom(
            Receipt(
                run_id=doc.run_id if doc is not None else -1,
                status="FAILED", rows_read=0, rows_loaded=0, rows_invalid=0,
                rows_deduplicated=0, duration_ms=0, report_uri=None,
            ),
        )
        raise
    finally:
        if pool is not None:
            pool.close()
```
`pool: ConnectionPool | None = None` and `doc: AssignmentDocument | None = None` are both initialized BEFORE the `try:` block -- `_build_common()` (the very first line inside `try:`) can itself raise before `doc` is ever assigned, which is why the existing `except DataPlatformError:` branch already guards with `doc.run_id if doc is not None else -1`. The new `except Exception:` branch must use the identical guard.

`_write_xcom(payload: dict[str, object] | Receipt) -> None` already writes to `Path(os.environ.get("DATAPLAT_XCOM_PATH", _DEFAULT_XCOM_PATH))`, creating parent directories, serializing a `Receipt` via `.model_dump_json()` -- unchanged by this plan.

From `packages/dataplat/src/dataplat/errors.py` (current, unchanged -- `except Exception:` is a strict superset of this hierarchy, never a subset; Python's except-clause ordering means `except DataPlatformError:` still catches every `DataPlatformError` subclass first, and `except Exception:` only ever sees what the first clause did not match):
```python
class DataPlatformError(Exception): ...
class ConfigurationError(DataPlatformError): ...
class StorageError(DataPlatformError): ...
class SecretResolutionError(DataPlatformError): ...
```

This plan's fix only changes whether a Receipt gets written before that propagation -- it does not change what `main()` catches.
