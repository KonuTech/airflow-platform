## Operational Observations (non-blocking — not gaps against any declared must-have)

These do not fail any must-have declared in the 13 plans' frontmatter (cross-checked against
`.planning/REQUIREMENTS.md` and the ROADMAP goal, which has no separate numbered success-criteria
list for this inserted phase), but are worth surfacing to the developer:

1. **`silver.orders` is currently empty (0 rows) on the live cluster**, while `normalized.orders`
   still holds 6 pre-existing gold rows from the old (pre-08.1) pipeline. This is not a code defect:
   `08.1-13-PLAN.md`'s own must-haves and Task 3 explicitly scope the live D-16 backfill proof to
   `csv_ingest_customers` only (`airflow dags backfill -d csv_ingest_customers ...`), and
   `08.1-REVIEW.md`'s WR-03 independently flags the same "one dataset, one happy path" scope for the
   live E2E suite. The orders dedup/incremental *mechanism* is fully built and proven correct via
   `test_dbt_silver_dedup.py`'s orders-specific test and `test_dbt_silver_incremental.py` (both
   pass live against testcontainers). Recommend a follow-up live backfill run for
   `csv_ingest_orders` to bring `silver.orders` to parity with `normalized.orders`, but this is an
   operational/data-completeness task, not a code gap in this phase's deliverables.

2. **The live kind cluster is currently in a degraded state**, observed during this verification
   session and unrelated to phase 08.1's code: `vault-0` is `Sealed` (`vault status` confirms
   `Sealed: true`), and one Airflow task pod
   (`csv-ingest-customers-build-stage-args-j7ltwdro`) is stuck in `Unknown` status with a
   `FailedMount` event on the `config` ConfigMap volume. All cluster pods show a restart ~29
   minutes prior to this check, consistent with the known WSL2/kind host-restart fragility already
   documented in this project's own memory notes ("a host restart can silently break kind's DAGs
   mount and freeze Airflow scheduling cluster-wide"). This will block any further live DAG runs
   (dbt_build/publish need Vault-delivered credentials) until an operator unseals Vault
   (`vault operator unseal`) and the orphaned pod is cleaned up. Not a phase 08.1 regression — the
   CR-01 fix, migrations, and Airflow Variable were all independently confirmed correct on the live
   cluster's *persistent* state (PostgreSQL, container registry, Airflow metadata DB) before/despite
   this transient pod-level degradation.
