# Phase 08.1 Plan 11: stage/publish CLI subcommands Summary

**Replaced `csv_processor.cli`'s single `ingest` command with `stage`/`publish`, wiring plan 08.1-10's `stage_ingest`/`publish_ingest` split into the CLI surface plan 08.1-12's DAG tasks will invoke -- and, going beyond the plan's own literal file list, fixed the resulting `make test` breakage the prior wave deliberately left behind.**

## Performance

- **Duration:** ~25 min
- **Tasks:** 2 completed (plus one orchestrator-directed follow-up fix)
- **Files modified:** 4 (1 created-command-file untouched structurally; 3 test files + 1 tracking doc)

## Accomplishments

- `stage` reproduces `ingest`'s entire prologue byte-for-byte (assignment fetch/validate, `ConfigRegistry.get_by_id`, multipart-parts resolution, `get_or_create_dataset`, `RunContext`/`PipelineContext` construction with a real `CsvSource`) and calls `stage_ingest` in place of the removed `run_ingest` -- `grep -n "^def ingest"` returns no match, `mypy packages/csv-processor/` exits 0, and `python -c "from csv_processor.cli import stage, publish"` succeeds.
- `publish` is genuinely new and lighter: mirrors `discover`'s shape (no assignment document, no `CsvSource`), builds a sentinel `run_id=0` `RunContext` for tracing/log correlation only, and calls `publish_ingest(ctx)` -- `ctx.source` stays `None`, proven live by `test_publish_never_constructs_a_csv_source`.
- Both commands keep the receipt/dict-on-every-exit-path contract (`except DataPlatformError` / `except Exception` / `finally: pool.close()`), proven by 4 renamed `test_stage_*` tests (WR-01's regression coverage, now for `stage`) and 3 new `test_publish_*` tests (success, `DataPlatformError` failure payload, no-`CsvSource` guarantee) -- 8/8 pass fully offline in `tests/unit/test_csv_processor_cli.py`.
- Beyond this plan's own declared scope: `tests/unit/test_run_ingest_trace.py` still imported the removed `run_ingest` directly, aborting `make test`'s entire collection (0 tests run, nonzero exit) before Task 1 even ran -- migrated all 5 of its tracing/metrics behavior tests to `stage_ingest` (span renamed `pipeline.stage_ingest`, receipt status `"STAGED"`, failure injection moved from a `resolve_publisher` boom to a `StagingLoader` boom since `stage_ingest` no longer touches `resolve_publisher` at all), dropping only the one behavior (`pipeline.publish` as a child span of the run span) that no longer exists structurally after the split. `pytest tests/unit tests/regression -q --cov` now passes clean: **496 passed, 0 errors**.

## Decisions Made

- **`publish`'s except-clause shape**: implemented `except DataPlatformError` AND `except Exception` (not just the former, which is all `discover`'s real code has). The plan's own action text cited both "the SAME shape as `discover`" (which lacks `except Exception`) and, separately, an `except Exception` clause -- an internal ambiguity. Resolved by following the threat model's explicit T-08.1-27 mitigation text, which states plainly that "Both `stage` and `publish` keep the `except DataPlatformError` / `except Exception` / `finally` shape" -- treated as a correctness requirement per the execution rules' threat-model guidance (Rule 2).
- **Migrating `test_run_ingest_trace.py` outside this plan's declared `files_modified`**: the orchestrator's own objective for this plan explicitly named this file's `ImportError` as the reason the entire `tests/unit` suite failed to collect (a genuine blocking issue, Rule 3), and instructed treating a clean `make test` run as part of this plan's success criteria even where the plan file itself doesn't say so. Migrated rather than deleted, preserving 5 of 6 original behavior tests (tracing propagation, metrics emission) against `stage_ingest`; dropped the 6th (`publish` span as a child of the run span) since that parent-child relationship no longer exists after the D-04 split -- `publish_ingest` opens its own unrelated `pipeline.publish` span, never nested under `pipeline.stage_ingest`.
