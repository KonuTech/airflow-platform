<objective>
Build the phase's central deliverable: two dbt incremental models (`silver_customers`,
`silver_orders`) that together implement DEDUP-01 through DEDUP-04, INCR-03, INCR-04 and QUAL-10
— the whole "duplicate/late-arriving-event resolution" capability this phase exists to deliver,
using dbt's own incremental-model machinery as the strategy interface (never `SELECT DISTINCT`).

**D-06's non-negotiable shape**: the incremental filter keys off the monotonic `_run_id`
lineage column, never `event_ts` — a late-arriving row with an old `event_ts` but a NEW `_run_id`
must still be picked up by `is_incremental()`; `event_ts` is used only to resolve ordering AMONG
rows the filter already selected.

**D-07's two dedup layers, concretely resolved here** (RESEARCH.md's Pattern 1 left the
secondary hash layer's exact design to planning): (1) **business-key layer** — the model's own
`row_number() over (partition by <business_key> order by event_ts desc, _source_row_number desc)
= 1` filter is what actually determines silver's deduplicated state (this platform's one existing
tie-break rule, carried forward verbatim from `merge.py`'s own `DISTINCT ON` precedent). (2)
**exact-row-hash layer** — operates inside the post-hook's audit classification, not as a second
independent filtering pass: among the rows the ranking DROPPED (`rn > 1`), a dropped row sharing
the WINNER's exact `_record_hash` is classified `EXACT_DUP_IN_FILE`/`EXACT_DUP_CROSS_BATCH`
(true duplicate content); a dropped row with a DIFFERENT hash is classified `SUPERSEDED_BY_NEWER`
(a genuine, later correction). Both layers read the SAME ranked CTE — one filters, one classifies.

Purpose: this is where DEDUP-01..04/INCR-03/INCR-04/QUAL-10 actually get implemented and proven —
every other plan in this phase exists to support this one.
Output: the full `dbt/` project (scaffolding, both silver models, the shared post-hook macro),
plus four integration test files proving DEDUP-01..04/INCR-03/04/QUAL-10 against a real
testcontainers PostgreSQL running real `dbt build` invocations.
</objective>
