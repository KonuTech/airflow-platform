<objective>
Add a `multi_node` pytest marker that skips, under a live cluster with fewer than 3 nodes, exactly the 5 tests whose assertions are about cluster-wide topology SHAPE (node count, Postgres-primary node placement, node-name list, full Deployment-name set) rather than any single component's health. These 5 tests are structurally correct for the local persistent 3-node cluster and structurally inapplicable to CI's deliberately single-node profile — this is a disclosed, deliberate narrowing of `make cluster-verify`'s CI-invoked scope, not a test rewrite or a weakening of local coverage.

<why_live_detection_not_profile_env_var>
`.github/workflows/e2e-full.yml`'s "Bring up the ephemeral kind cluster (CI profile)" step sets `PROFILE=ci` only as an inline prefix on that one `run: PROFILE=ci make cluster-up` line — it is never written to `$GITHUB_ENV`, so it does not persist into the later "Run the full local E2E suite (make cluster-verify)" step (a bare `run: make cluster-verify`, no PROFILE anywhere). Makefile's `cluster-verify` target itself also never references `$(PROFILE)` today. A `PROFILE`-env-var read inside a test or conftest.py would therefore silently evaluate to unset/`"local"` even when running against a genuinely CI-profile (single-node) cluster — reproducing the exact propagation-gap bug class quick task 260824-akz already found and fixed for `make chaos-verify` (see its SUMMARY.md's "key-decisions"), just for a different mechanism (skip vs. kubectl-exec-target).
</why_live_detection_not_profile_env_var>

<why_no_workflow_or_makefile_changes>
Because the skip decision is made by a LIVE kubectl node-count probe inside `tests/e2e/cluster/conftest.py` (not by reading an environment variable), nothing needs to be threaded through `Makefile`'s `cluster-verify` target or `.github/workflows/e2e-full.yml` for the skip to take effect correctly. `kind/cluster.yaml` (local profile) always declares 3 nodes; `kind/cluster-ci.yaml` (CI profile, confirmed by reading it: `nodes: - role: control-plane`, nothing else) always declares exactly 1. Node count is therefore a structural, always-correct, zero-configuration signal — it works identically whether invoked via `make cluster-verify` locally, via `e2e-full.yml`, or via a bare `pytest tests/e2e/cluster` in any environment, with no dependency on GitHub Actions env propagation ever being wired correctly. This is deliberately NOT the same mechanism as a `-m "not multi_node"` deselection flag threaded through the Makefile/workflow — that approach was considered and rejected specifically because it would reintroduce the same PROFILE-propagation fragility this plan (and its 260824-akz sibling) exist to avoid.
</why_no_workflow_or_makefile_changes>
