<why_live_detection_not_profile_env_var>
The obvious mirror of `scripts/stages/70-airflow.sh`'s own fix would be a `PROFILE` environment-variable branch. This is WRONG here and must not be used: `.github/workflows/e2e-chaos.yml` sets `PROFILE=ci` only as an inline prefix on the separate `make cluster-up` step; it is never written to `$GITHUB_ENV`, so it does not persist into the later `make chaos-verify` step that actually runs this pytest file. `Makefile`'s `chaos-verify` target (`pytest tests/e2e/chaos tests/e2e/vault -q -m cluster`) never threads `PROFILE` through either. A `PROFILE`-env-var read inside this test file would silently default to `"local"` even on a genuinely CI-profile cluster, reproducing this exact bug under a different mechanism. Live-querying which object kind the chart actually rendered (`kubectl -n airflow get deployment/statefulset airflow-scheduler`) is authoritative regardless of what the calling process's environment does or doesn't carry — the same reasoning `tests/e2e/chaos/test_vault_unavailable.py`'s own `_scheduler_resource_ref` docstring already documents for the sibling fix.
</why_live_detection_not_profile_env_var>

<why_a_bare_kind_string_not_a_kind_ref>
`test_vault_unavailable.py`'s `_scheduler_resource_ref` returns a full `"deploy/airflow-scheduler"` / `"statefulset/airflow-scheduler"` ref string, because its own call sites pass that ref straight into `kubectl exec <ref> -- ...`. This file's loop shape is different: `test_airflow_conn_minio_default_is_absent_from_every_component` iterates `for kind, names in (("deployment", _DEPLOYMENTS), ("statefulset", _STATEFULSETS)): for name in names: kubectl_json("-n", NAMESPACE, "get", kind, name)` — `kind` and `name` are always two separate positional arguments to `kubectl_json`, never a combined ref string. The new helper for this file must therefore return a bare kind string (`"deployment"` or `"statefulset"`), not a ref, so it slots into that existing two-argument call shape without restructuring the loop.
</why_a_bare_kind_string_not_a_kind_ref>
